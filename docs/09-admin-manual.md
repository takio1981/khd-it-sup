# 9. Admin Manual (คู่มือผู้ดูแลระบบ)

สำหรับ **Super Admin, Admin, และ IT Officer** — ดูสิทธิ์แต่ละ Role โดยละเอียดที่
[docs/01-architecture.md § Permission Matrix](01-architecture.md)

## 9.2 การจัดการครุภัณฑ์

1. เมนู **"ครุภัณฑ์"** → กด **"เพิ่มครุภัณฑ์"**
2. เลือกประเภทครุภัณฑ์ (14 ประเภทตามที่ระบบรองรับ: คอมพิวเตอร์, โน้ตบุ๊ก, เครื่องพิมพ์, เครื่องสแกน, UPS, สวิตช์, เราเตอร์,
   ไฟร์วอลล์, เซิร์ฟเวอร์, จอภาพ, โปรเจกเตอร์, เครื่องปรับอากาศ, ครุภัณฑ์การแพทย์, อื่น ๆ)
3. กรอกยี่ห้อ/รุ่น/Serial Number/เลขครุภัณฑ์ราชการ/หน่วยงานที่ครอบครอง
4. ระบบจะ**สร้างเลขครุภัณฑ์ภายในให้อัตโนมัติ** (รูปแบบ `IT-000001`, `IT-000002`, ...) — ไม่ต้องกรอกเอง
5. แก้ไข/ลบครุภัณฑ์ทำได้ผ่านเมนู "⋮" ท้ายแถวตาราง (การลบเป็น soft-delete เพื่อรักษาประวัติงานซ่อมเก่า)
6. เมนูย่อย **"ประเภทครุภัณฑ์"** และ **"สถานที่ตั้ง"** (อาคาร/ชั้น/ห้อง) จัดการได้จาก "จัดการสถานที่/หน่วยงาน"

### การสร้างและพิมพ์ QR Code

1. ที่หน้ารายละเอียดครุภัณฑ์ กด **"สร้าง QR"** — ระบบจะเข้ารหัส (AES-256) รหัสอ้างอิงครุภัณฑ์ฝังลงใน QR
2. กด **"พิมพ์ QR"** เพื่อดาวน์โหลดไฟล์ QR ความละเอียดสูงสำหรับพิมพ์ติดสติกเกอร์
3. **หากสร้าง QR ใหม่ (regenerate)** สติกเกอร์เดิมที่พิมพ์ไปแล้วจะใช้งานไม่ได้ทันที — ใช้เมื่อสงสัยว่า QR เดิมรั่วไหล/เสียหายเท่านั้น
4. รองรับการพิมพ์หลายรายการพร้อมกัน (Bulk Print) ผ่านหน้ารายการครุภัณฑ์

## 9.3 การจัดการงานแจ้งซ่อม (IT Officer / Admin)

### ขั้นตอนมาตรฐาน (Internal Repair)

```
แจ้งซ่อมแล้ว → รับเรื่องแล้ว → ตรวจสอบเบื้องต้น → วิเคราะห์ปัญหา
   → [รออะไหล่] → กำลังซ่อม → ทดสอบระบบ → ซ่อมเสร็จสิ้น
   → คืนอุปกรณ์แล้ว → ผู้แจ้งรับมอบ → ปิดงาน
```

1. เมนู **"งานแจ้งซ่อม"** จะแสดงใบแจ้งซ่อมทั้งหมดในระบบ (ต่างจากผู้ใช้ทั่วไปที่เห็นเฉพาะของตน)
2. เปิดใบแจ้งซ่อมที่มีสถานะ "แจ้งซ่อมแล้ว" แล้วกด **"รับเรื่อง"**
3. กด **"มอบหมายช่าง"** เพื่อเลือกช่างเทคนิค/เจ้าหน้าที่ไอทีที่จะรับผิดชอบ (ไม่เปลี่ยนสถานะ workflow โดยตรง — เป็นแค่การกำหนดผู้รับผิดชอบ)
4. ใช้เมนู "⋮" มุมขวาบนเพื่อ **"เปลี่ยนสถานะ"** ไปยังขั้นตอนถัดไปตาม workflow ที่กำหนดไว้ — ระบบจะแสดงเฉพาะสถานะถัดไปที่
   เป็นไปได้จริงเท่านั้น (ป้องกันการข้ามขั้นตอน)
5. เมื่อถึงขั้น "ผู้แจ้งรับมอบ" แล้ว กด **"ปิดงาน"** เพื่อจบกระบวนการ
6. หากต้องการยกเลิกงาน ใช้ปุ่ม **"ยกเลิกงาน"** ซึ่งบังคับให้ระบุเหตุผลเสมอ
7. ไฟล์แนบ (รูป/วิดีโอ) แนบได้สูงสุด 5 ไฟล์ต่อครั้ง — Timeline จะแสดงทุกไฟล์ที่แนบไว้ครบ ไม่ใช่แค่ไฟล์แรก

> **หมายเหตุ:** ขั้นตอนซ่อมภายนอก (External Repair) 14 ขั้นตอนแบบเต็ม, ระบบอนุมัติหลายลำดับ (Multi-level Approval),
> และ Visual Flow Designer สำหรับปรับแต่ง workflow เอง อยู่ใน **Phase 10+** ตาม [roadmap](00-roadmap.md)

### Timeline (บันทึกถาวร)

ทุกการกระทำ (รับเรื่อง, มอบหมาย, เปลี่ยนสถานะ, แนบไฟล์, คอมเมนต์, ยกเลิก) จะถูกบันทึกลง Timeline โดยอัตโนมัติ
พร้อมเวลา ผู้กระทำ และ SLA ของขั้นตอนนั้น — **ข้อมูลนี้แก้ไขหรือลบไม่ได้แม้แต่ผู้ดูแลระบบสูงสุด** (บังคับที่ระดับฐานข้อมูล)
เพื่อความโปร่งใสในการตรวจสอบย้อนหลัง

## 9.4 การจัดการยืม-คืนครุภัณฑ์

1. เมนู **"ยืมครุภัณฑ์-อุปกรณ์"** → กด **"ยืมอุปกรณ์"**
2. เลือกครุภัณฑ์ (ต้องไม่มีรายการยืมค้างอยู่) ผู้ยืม กำหนดวันที่ต้องคืน วัตถุประสงค์ และสภาพครุภัณฑ์ ณ วันยืม
3. ระบบจะแจ้งเตือนผู้ยืมทันทีที่บันทึก (อีเมล/Telegram/LINE/กระดิ่งในแอป ตามที่เปิดใช้งาน)
4. เมื่อคืน กดที่รายการ → **"บันทึกคืน"** พร้อมระบุสภาพครุภัณฑ์ ณ วันคืน
5. รายการที่เกินกำหนดคืน (สถานะ "เกินกำหนดคืน") จะถูก**แจ้งเตือนผู้ยืมซ้ำทุกวัน (08:00) โดยอัตโนมัติ**จนกว่าจะมีการบันทึกคืน
   — ปิดการแจ้งเตือนนี้ได้ที่ § 9.7

## 9.5 การจัดการผู้ใช้งาน (Admin/Super Admin)

1. เมนู **"ผู้ใช้งาน"** → **"เพิ่มผู้ใช้"**
2. กรอกชื่อผู้ใช้/อีเมล/รหัสผ่านเริ่มต้น/ชื่อ-นามสกุล/เพศ (ใช้เลือกภาพ avatar เริ่มต้น) เลือก Role, หน่วยงาน และตำแหน่งงาน
3. ผู้ใช้ใหม่จะถูกบังคับให้เปลี่ยนรหัสผ่านในการเข้าสู่ระบบครั้งแรกเสมอ
4. **แก้ไขผู้ใช้**: อัปโหลด/ลบรูปโปรไฟล์ให้ผู้ใช้แต่ละคนได้จากฟอร์มแก้ไข (ปุ่ม "เปลี่ยนรูป"/"ลบรูป")
5. **รีเซ็ตรหัสผ่าน**: ใช้เมื่อผู้ใช้ลืมรหัสผ่านและเข้าถึงอีเมลตัวเองไม่ได้ ระบบจะสุ่มรหัสผ่านชั่วคราวส่งเข้าอีเมลผู้ใช้ให้อัตโนมัติ
   (ผู้ใช้ส่วนใหญ่ไม่จำเป็นต้องพึ่งขั้นตอนนี้แล้ว เพราะมีปุ่ม "ลืมรหัสผ่าน?" แบบ self-service ที่หน้า login ให้ใช้เองได้)
6. **ลบผู้ใช้**: เป็น soft-delete (ปิดใช้งานบัญชี ไม่ลบข้อมูลถาวร) เพื่อรักษาความสัมพันธ์กับใบแจ้งซ่อม/audit log เดิม

### ตำแหน่งงาน

เมนู **"ผู้ใช้งาน"** → **"จัดการตำแหน่งงาน"** สำหรับเพิ่ม/แก้ไขตำแหน่งงาน (คำนำหน้า/ตำแหน่ง) ที่ผูกกับผู้ใช้แต่ละคน

## 9.6 การจัดการหน่วยงาน

เมนู **"จัดการสถานที่/หน่วยงาน"** รองรับ:
- **หน่วยงาน** (Department) — โครงสร้างแบบลำดับชั้น (หน่วยงานแม่-ลูก) ใช้จัดกลุ่มผู้ใช้และครุภัณฑ์
- **แผนก** (Division) — หน่วยย่อยภายในหน่วยงาน
- **สถานที่** (Building/Floor/Room) — ตำแหน่งจริงของครุภัณฑ์

## 9.7 แดชบอร์ด

หน้า **"แดชบอร์ด"** แบ่งเป็นหลายแท็บตามโมดูล (งานแจ้งซ่อม / ครุภัณฑ์ / ยืม-คืนครุภัณฑ์-อุปกรณ์ / ผู้ใช้งาน /
ตำแหน่งงาน / หน่วยงาน / แผนก / การแจ้งเตือน) แต่ละแท็บแสดง:

- การ์ดสรุปสถิติของโมดูลนั้น (เช่น งานรอดำเนินการ, เสร็จสิ้นแล้ว, รออะไหล่, ยกเลิก, กำลังยืม, เกินกำหนดคืน)
- กราฟจำนวนใบแจ้งซ่อม/รายการยืม-คืนรายเดือน
- อันดับหน่วยงาน/ครุภัณฑ์/ผู้ยืมที่มีกิจกรรมมากที่สุด
- ภาระงานของช่างเทคนิคแต่ละคน (งานที่ยังไม่ปิด)

> รายงานแบบ Export Excel/PDF/CSV และ Audit Log UI แบบเต็มรูปแบบอยู่ใน Phase 10+

## 9.8 การแจ้งเตือน

เมนู **"ตั้งค่าแจ้งเตือน"** มี 2 แท็บ:

### แท็บ "ประวัติการแจ้งเตือน"

แสดงประวัติการส่งแจ้งเตือน**ทุกช่องทาง**พร้อมสถานะการส่ง (ส่งสำเร็จ/ล้มเหลว/รอส่ง) กรองตามช่องทาง (Email/Telegram/LINE/Push)
และสถานะได้ — ช่องทาง "Push" คือแจ้งเตือนในแอป (กระดิ่ง) ของผู้ใช้แต่ละคน

### แท็บ "ตั้งค่า" (ต้องมีสิทธิ์ `settings:manage`)

1. **เปิด/ปิดช่องทางแจ้งเตือน** — อีเมล, Telegram, LINE (มีผลทันทีไม่ต้อง restart)
2. **ตั้งค่า Telegram Bot** — กรอก Chat ID + Bot Token (สร้างผ่าน `@BotFather`) เพื่อส่งเข้ากลุ่ม/แชทกลาง
3. **ตั้งค่า LINE Messaging API** — กรอก Group ID/User ID + Channel Access Token
4. **เลือกประเภทเหตุการณ์ที่ต้องการแจ้งเตือน** แยกเปิด/ปิดได้ทีละประเภท: มีใบแจ้งซ่อมใหม่, มอบหมายงาน, สถานะเปลี่ยนแปลง,
   งานเสร็จสิ้น, งานถูกยกเลิก, มีการยืม/คืนครุภัณฑ์, **ยืมเกินกำหนดคืน** (แจ้งซ้ำทุกวันเวลา 08:00 จนกว่าจะคืน)

Bot Token/Access Token จะไม่แสดงค่าจริงกลับมาที่หน้าจออีกครั้งหลังบันทึก (แสดงแค่สถานะว่าตั้งค่าไว้แล้วหรือยัง) เพื่อความปลอดภัย

## 9.9 การตั้งค่าระบบทั่วไป

เมนู **"ตั้งค่าทั่วไป"** (`/settings/general`, ต้องมีสิทธิ์ `settings:manage` เพื่อแก้ไข — ผู้มีสิทธิ์ `audit:view` ดูได้อย่างเดียว):

1. **ข้อมูลองค์กร** — ชื่อองค์กร (แสดงบน topbar ทุกหน้า) และโลโก้ (แสดงที่มุมบนซ้ายของแถบเมนู แทนที่โลโก้ default
   หลังบันทึกต้อง refresh หน้าจอ 1 ครั้งเพื่อให้ทุกจุดในแอปใช้ค่าใหม่)
2. **SMTP Server** — Host/Port/SSL(secure)/ผู้ใช้/รหัสผ่าน/อีเมลผู้ส่ง/ชื่อผู้ส่ง มีผลทันทีกับการส่งอีเมลครั้งถัดไปโดยไม่ต้อง
   restart backend (ถ้ายังไม่ตั้งค่าที่นี่ ระบบใช้ค่าจาก `.env` เป็นค่าเริ่มต้น) รหัสผ่านที่ตั้งไว้แล้วจะไม่แสดงค่าจริงกลับมาหน้าจอ
   (เหมือน Telegram/LINE Token — ดู § 9.8) เพื่อความปลอดภัย
3. **สีธีมหลัก** — บันทึกค่า hex ไว้ในระบบแล้ว แต่ยังไม่ผูกเข้ากับธีมของ Angular Material แบบ runtime ในเวอร์ชันนี้
   (เตรียมโครงสร้างข้อมูลไว้รองรับ Phase ถัดไป)

ก่อนหน้านี้ค่าทั้งหมดนี้ตั้งได้เฉพาะผ่าน Environment Variable (`.env`) + rebuild เท่านั้น — ดู
[docs/06-installation-guide.md](06-installation-guide.md)

## 9.10 ประวัติการใช้งานระบบ (Audit Log)

เมนู **"ประวัติการใช้งานระบบ"** (ต้องมีสิทธิ์ `audit:view`) แสดงประวัติการกระทำทุกโมดูลในระบบ (login/logout, สร้าง/แก้ไข/ลบ
ข้อมูล, พิมพ์เอกสาร, ส่งออกข้อมูล, อนุมัติ, เปลี่ยนแปลงการตั้งค่า) — บันทึกอัตโนมัติทุกครั้ง แก้ไข/ลบไม่ได้
(ตาราง `audit_logs` บังคับด้วย MariaDB trigger เช่นเดียวกับ Timeline ของงานแจ้งซ่อม)

กรองได้ตาม **โมดูล** (พิมพ์ค้นหา เช่น `repair-tickets`, `assets`, `auth`), **การกระทำ**, และ **ช่วงวันที่** —
แต่ละแถวแสดงเวลา ผู้ใช้ที่กระทำ การกระทำ โมดูล รายละเอียด และ IP Address ที่ใช้เชื่อมต่อ
